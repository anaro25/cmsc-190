\section{Branches}

The experiment currently uses nine map types grouped into two study families.

\subsection{Traditional MAPF}
\begin{itemize}[leftmargin=2em]
    \item \textbf{Static artificial}: dispersed starts to dispersed targets.
    \item \textbf{Static port}: dispersed starts to clustered targets.
    \item \textbf{Dynamic port}: clustered starts to clustered targets.
\end{itemize}

\subsection{Campus Crowd Simulation}
\begin{itemize}[leftmargin=2em]
    \item \textbf{Static campus\_area\_1}: dispersed starts to one shared single target.
    \item \textbf{Dynamic campus\_area\_1}: clustered starts to one shared single target.
    \item \textbf{Static campus\_area\_2}: dispersed starts to one shared single target.
    \item \textbf{Dynamic campus\_area\_2}: clustered starts to one shared single target.
    \item \textbf{Static campus\_area\_3}: dispersed starts to one shared single target.
    \item \textbf{Dynamic campus\_area\_3}: clustered starts to one shared single target.
\end{itemize}

\section{Assignment Model}

Branches normally use one-to-one MAPF assignments when goals are \texttt{dispersed} or \texttt{clustered}. The project also supports a target-only \texttt{single} goal distribution mode, where all agents share one literal target cell and disappear there after arrival. What changes across branches is therefore both the \emph{positioning} of starts and goals and, when \texttt{single} is selected for targets, the assignment cardinality.

\section{Campus Semantics}

For the campus branches, zone colors are traversable and spawnable for agents and targets, white walkways are traversable but non-spawnable for agents and targets, and gray regions are non-traversable. Dynamic campus branches generate dynamic obstacles on all campus traversable cells, including both zone colors and white walkways. Static and dynamic variants of the same campus area both use the same campus source image.

\section{Placement Rule}

Within a sampled run configuration, \texttt{dispersed} sets keep 8-neighbor separation internally. Clustered sets are controlled by the global \texttt{compact\_clustering} switch: when it is \texttt{True}, clustered sets are directly adjacent 8-neighbor-connected groups; when it is \texttt{False}, clustered sets stay connected while keeping one empty cell of separation in all 8 directions. The \texttt{single} mode applies only to targets and samples one shared target cell from the darker marker cells in the selected campus target zone. Start-goal adjacency is allowed, but a start and its assigned goal cannot be the same cell.

\section{Supplementary Reference Comparison}

A separate supplementary workflow is available for the Tang-inspired reference comparison. This workflow is controlled from \texttt{dev/master\_config\_ref\_comparison.py} and is selected from \texttt{dev/main.py} by choosing \texttt{SELECTED\_EXPERIMENT = "ref\_comparison"}. The main experiment remains controlled by \texttt{dev/master\_config.py}.

The reference comparison uses only the 20x20 and 50x50 binary port maps in \texttt{dev/inputs/reference\_port\_maps/}. Pure black pixels are obstacles and pure white pixels are free spaces. The start location is the lower-left-most free cell and the target location is the upper-right-most free cell. Any sibling images containing manually colored path markings are left in the input directory for record-keeping but are not used by the program.

The reference workflow mirrors the main experiment workflow: \texttt{recompute\_MAPF} controls whether raw solver data is recomputed, while \texttt{to\_generate} controls whether graphs/data, visualizations, or nothing are generated from saved raw data.

The reference workflow also has its own cyclic-map transition-processing toggles:

\begin{lstlisting}
REMOVE_EXTRA_TRANSITIONS = False
ADD_TRANSITIONS_BETWEEN_FREE_SPACES = False
\end{lstlisting}

When \texttt{REMOVE\_EXTRA\_TRANSITIONS} is \texttt{True}, cyclic mapping keeps the full final cleanup step that removes redundant bidirectional transitions. When this is \texttt{False}, the reference comparison skips only the redundant-transition elimination step while still preserving required connectivity restoration. When \texttt{ADD\_TRANSITIONS\_BETWEEN\_FREE\_SPACES} is \texttt{True}, a bidirectional transition is added between every adjacent pair of free cells after the cyclic-mapping cleanup steps. These toggles only affect the reference comparison and do not change the main experiment.

The selectable reference cases are:

\begin{lstlisting}
# SELECTED_PORT_EXPERIMENT = "single_agent"
SELECTED_PORT_EXPERIMENT = "multi_agent"
\end{lstlisting}

The single-agent reference case compares traditional A* on classical mapping against traditional A* on cyclic mapping across three separate 50x50 port maps: \texttt{port\_map\_1.png}, \texttt{port\_map\_2.png}, and \texttt{port\_map\_3.png}. The older orientation-based variants are no longer generated. For each map, the start remains the lower-left-most free cell and the goal remains the upper-right-most free cell. For each single-agent map and mapping, \texttt{SINGLE\_AGENT\_TIMING\_REPETITIONS = 5} repeats the same deterministic A* setup five times and stores the average runtime. The path, node, turn, and distance values are still produced from the same unchanged setup. The multi-agent reference case uses the same three-map structure with ECBS on classical mapping against ECBS on cyclic mapping. Each port map has its own configurable agent count through \texttt{MULTI\_AGENT\_REFERENCE\_PORT\_MAP\_AGENT\_NUMBERS}. For each multi-agent map and mapping, \texttt{MULTI\_AGENT\_TIMING\_REPETITIONS = 3} repeats the same deterministic release/spawn setup three times and stores the average runtime. The temporary individual cyclic-faster filter is disabled.

Reference outputs are stored separately from the main experiment under \texttt{dev/outputs\_ref\_comparison/}. Each case has an independent output folder such as \texttt{single\_agent} or \texttt{multi\_agent}. Reference graph/data generation writes a matplotlib-formatted summary table beside the graphs, with separate sections for map numbers 1, 2, and 3. Single-agent tables report nodes, turns, and total distance; multi-agent tables replace nodes with conflicts and label the path-related values as averages across agents. When \texttt{to\_generate = "visualization"}, reference visualization selection is performed independently for each map number and mapping, so all three port map types are represented when solved candidates exist. The visualization phase logs the candidate selection, each map/mapping being rendered, frame-writing stages, and final frame counts.
