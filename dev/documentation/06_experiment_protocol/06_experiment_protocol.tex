\section{Current Main-Experiment Structure}

The main experiment is organized around map configurations. Selecting a map category in \texttt{master\_config.py} runs every documented layout configuration for that category. Across all categories, the design contains forty configurations.

For each configuration, classical mapping and cyclic mapping are tested independently. The goal is to find two capacity values:
\[
\Nclass = \text{highest tested agent number passed by classical mapping},
\]
\[
\Ncyc = \text{highest tested agent number passed by cyclic mapping}.
\]

\section{Limited Binary-Search Capacity Testing}

The tested range is fixed at:
\[
1 \leq N \leq 255.
\]

The values are treated as nodes of a complete binary search tree whose root is 128. A pass moves the search to the right child. A failure moves the search to the left child.

The search no longer continues until a leaf node. It stops after the configured number of downward child moves from the root:

\begin{lstlisting}
CAPACITY_BINARY_SEARCH_MAX_DOWNWARD_MOVES = 3
\end{lstlisting}

For example, one possible traversal is:

\begin{lstlisting}
128 -> 64 -> 32 -> 48
\end{lstlisting}

With three downward moves, the furthest possible tested values are:

\begin{lstlisting}
16, 48, 80, 112, 144, 176, 208, 240
\end{lstlisting}

\section{Backtracking Behavior}

There is no separate manual backtracking phase. During traversal, the program stores the highest passed value seen so far. If a later tested value fails and the traversal moves left, the earlier passed value remains stored unless a higher tested value passes later.

\section{Pass/Fail Rule for a Tested Agent Number}

Each tested agent number permits up to five valid solver attempts. The current pass rule is:

\begin{lstlisting}
CAPACITY_ATTEMPTS_PER_AGENT_NUMBER = 5
CAPACITY_SUCCESSFUL_RUNS_REQUIRED = 1
SHARED_TIME_LIMIT_SECONDS = 30.0
\end{lstlisting}

A tested agent number passes as soon as one valid attempt solves within the time limit. It fails only when all five valid attempts are counted without any successful solution.

Setup-failed and unsolvable initial conditions are regenerated and do not count as valid attempts. The setup-generation cap per solver attempt is currently:

\begin{lstlisting}
SETUP_GENERATION_ATTEMPT_CAP_PER_SOLVER_ATTEMPT = 5
\end{lstlisting}

\section{Saved Capacity Runs and Comparative Runs}

Because the current rule needs only one successful run, each mapping keeps one successful capacity-run initial condition at its discovered capacity point. That condition is then reused for the opposite mapping.

At \(\Nclass\), the classical successful run is compared with cyclic mapping on the same initial condition. At \(\Ncyc\), the cyclic successful run is compared with classical mapping on the same initial condition.

This gives paired evidence at both discovered capacity points while avoiding averages over multiple successful capacity runs.

\section{Logging Expectations}

Console and file logs separate solver attempts with blank lines so that successive runs are easier to read. After each tested agent number, the log also prints the elapsed time from the start of the experiment execution.
